# Change report: Ruchira POS v4 security release

Legend: **Fixed (code)** = implemented and covered by a test that was actually run. **Fixed (code, untested)** = implemented and
compile/static-checked only, because the sandbox had no FastAPI/PostgreSQL/browser. **Needs operator** = depends on Supabase/Render.

| # | Finding | Status | Files | What changed | Evidence | Remaining risk |
|---|---|---|---|---|---|---|
| 1 | Stored XSS | **Fixed (code)** for the audited sinks and a full sweep; strict CSP **not yet enforced** | `frontend/app.js`, `frontend/actions.js`, `frontend/index.html`, `backend/app.py`, `backend/core.py` | Serialised objects in `onclick` removed (edit buttons now pass an id and look the record up). All 130 inline `on*` attributes became `data-on*`, run by a tokenising dispatcher (no eval, allow-list of 63 functions). `order_type`, `status`, `payment` now escaped; `jsArg` encodes quotes too. Inline `<script>` in print popups removed (the page starts printing). Server: `order_type` allow-list (Pickup/Delivery) on create AND update, 422 otherwise. CSP + other headers. | `node --test`: 9/9 (hostile payloads incl. the audit's `&quot;+alert(1)+&quot;`, every real handler string parses, zero inline handlers left). `core` tests for order types. | Not run in a real browser. CSP defaults to `report-only` for the strict policy: check the console, then `CSP_MODE=enforce`. Old rows already holding hostile text are safe because output is escaped. |
| 2 | Default credentials | **Fixed (code, untested against DB)** | `backend/app.py`, `backend/core.py`, `frontend/*`, `.env.example`, docs | No default account. Empty DB + no/weak `ADMIN_PASSWORD` = startup error. Server enforces `must_change_password` for every route except `/api/me`, `/api/me/password`, `/api/logout`. Existing account that still accepts `admin123` is flagged at startup (not deleted/reset). Owner-created logins/resets are temporary (forced change). Password policy 10 to 128 chars + common list. `README.txt` removed from `frontend/` and scrubbed copy moved to `docs/`. `/static` allow-lists js/css/images/fonts only. `AUTH_REQUIRED=false` ignored in production. | `core` tests: password policy, static allow-list (35 blocked/allowed cases). API tests written (`tests/test_api_security.py`), **not run**. | The old default was publicly published: rotate (docs section 5). Check the live site returns 404 for `/static/README.txt`. |
| 3 | Supabase exposure | **Needs operator** (migrations written, not executed) | `migrations/0002`, `0004`, `0005`, diagnostics, `docs/DEPLOYMENT.md` | RLS on all 8 tables, REVOKE from anon/authenticated/PUBLIC, default privileges, NOT VALID checks. Optional private schema (app supports `AUTH_SCHEMA`) and optional least-privilege role. App no longer runs DDL; it verifies the schema read-only. | SQL **never run** (no PostgreSQL available). | Live exposure was never inspected: run diagnostics 01. The app's `postgres` connection bypasses RLS, so RLS only protects the Data API. |
| 4 | Missing role checks | **Fixed (code, untested against DB)** | `backend/core.py` (matrix), `backend/app.py` | One matrix (`STAFF_ALLOWED`), deny-by-default, enforced in middleware **and** by an `OWNER` dependency on every owner route. Staff dish toggle allowed only when name/category/price unchanged. Frontend hides the buttons and stops loading reports/inventory for staff. Audit log lines for deletes/clears/price/user/settings changes. | `core` tests: 40 owner-only and 16 staff cases plus path tricks. Route-vs-matrix and 20-route staff 403 tests written, **not run**. | Staff can still cancel or edit orders (needed by the kitchen). Audit trail is server log only. |
| 5 | Order integrity | **Fixed (code, untested against DB)** | `backend/app.py`, `core.py`, `migrations/0003`, `frontend/app.js` | Negative/NaN/huge fees rejected (422); totals computed in Decimal server-side. Order number now assigned under `pg_advisory_xact_lock`; client number only a hint; unique indexes (only created if no duplicates; nothing renumbered). Order + items in one transaction with rollback. `client_request_id` makes a re-sent Confirm return the same order. | `core` tests: money, totals. Concurrency, duplicate-submit, rollback tests written, **not run**. | Needs migration 0003 for idempotency/uniqueness (code works without, with a warning). Bills printed before save can still show a different number if two devices race (existing alert). |
| 6 | Owner lockout | **Fixed (code)** | `backend/core.py`, `backend/app.py` | Limits are per (client address, username) and per address; username-only lock removed (it only raises a log alert). Address = Nth entry from the right of X-Forwarded-For (`TRUSTED_PROXY_HOPS`), malformed values fall back to the socket peer, IPv6 bucketed per /64. Password change has its own throttle. | 11 limiter/IP tests run and passing, including "attacker hammers owner, owner logs in from another address". | In-memory, per process; see docs section 7. |
| 7 | Missing dependency | **Fixed (code)** | `backend/requirements.txt`, `requirements.txt`, `requirements-dev.txt` | `psycopg[binary,pool]`; both files identical; dev file for tests. | Compile and stub-import only. `pip install` could not run (no network). | Render's actual build command was not inspected. |
| 8 | Time zones | **Fixed (code, untested against DB)** | `backend/core.py`, `backend/app.py`, `frontend/app.js` | UTC-aware time internally; IST month/day bounds converted to UTC for queries; India date for purchase default and demo seeds; connections set to UTC; frontend default month is India-local. Historical rows not rewritten. | 9 time tests run and passing (midnight IST, UTC date change, month ends, Dec rollover, leap Feb, tiling). Report test against DB written, **not run**. | Column type and legacy semantics unverified: run diagnostics 04 (rows made on a laptop in IST would be 5h30 off). |
| 9 | Low items | **Fixed (code)** except noted | many | `SEED_DEMO_DATA=false` default and ignored in production; demo reset disabled otherwise; startup DDL removed; generic errors + server-side logging; field length limits; pagination (`limit` default 1000/max 5000); body-size check; `_check_settings.py` and the unused root `app.js` removed (not imported anywhere; index.html loads `frontend/app.js`); starter categories no longer re-created every restart; Ruchira menu only with `SEED_RUCHIRA_MENU=true`. | Static review. | Body limit checks the header only. Least-privilege role is optional and unexecuted. |
| - | Multi-tenancy | **Documented, not changed** | `docs/DEPLOYMENT.md` s.7 | Treated as one instance per kitchen; isolation requirements written down. | n/a | No tenant model exists. |
